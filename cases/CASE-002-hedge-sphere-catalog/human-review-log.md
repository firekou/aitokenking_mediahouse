# 人工重讀時推翻分類器的紀錄

**分類器：** `scripts/triage_reels.py`（規則式）｜**錯誤率：** 仍為 `UNMEASURED`
**用途：** 每一筆都是分類器判 `WORTH_SKILL`、但人讀完後推翻的案例。

> **這份檔案存在的理由：** `classifier_error_rate` 是 `UNMEASURED`，
> 而「UNMEASURED」不該變成「所以不用管」。
> **每抓到一次誤判就記一次**，累積到有 ground truth 為止。
> 累積夠了才算得出錯誤率——在那之前，這裡的筆數是我們對它唯一的了解。

---

## FP-1 · `DZ40OG8GDqF` — 業配廣告被判為技巧片

| | |
|---|---|
| 分類器判定 | `WORTH_SKILL` |
| 人工判定 | **`SPONSORED` — 不做 skill** |
| 內容 | 推銷某個「AI 工作流社群／模板市集」網站，通篇是產品介紹與變現話術 |
| 為什麼騙過分類器 | 廣告文案本身就充滿「首先」「第二步」「上傳」「選擇」「調整參數」——**動作訊號全中，但那些動作是在描述那個網站的操作介面，不是在教一個技巧** |

**★ 這是分類器的第一個確認誤判，而它暴露的是規則的根本限制：**
規則數得出「有沒有動作句」，數不出「這些動作屬於誰」。
產品導覽與技巧教學在詞彙層面幾乎無法區分。

**要不要修規則？暫時不修。** 加「業配偵測」規則的風險是把真的技巧片也擋掉，
而目前 n=1。**先累積案例，不要用一個樣本去改一把尺。**

## DUP-1 · `DaiAah0Cj1h` — 與 `DawieKViDyb` 同主題

| | |
|---|---|
| 分類器判定 | 兩支都 `WORTH_SKILL`（分類器沒有去重能力） |
| 人工判定 | **合併** —— 內容併入 `skills/ai-script-tension/`，不另立 skill |
| 重疊處 | 兩支都講「三問」（主角想要什麼／誰在阻止他／失敗會失去什麼）、都講「給參考方向」、都講「生成十個走向再篩選」 |
| 差異處 | `DawieKViDyb` 的反轉分**五個方向**（人物身份／動作／道具／聲音／鏡頭）；`DaiAah0Cj1h` 的反轉分**三層遞進**（身份／動機／局勢）。兩者互補，已都寫進同一支 |

**★ `triage.json` 的 verdict 值域裡有 `DUPLICATE`，但分類器沒有實作偵測。**
去重目前完全靠人讀。**這是已知缺口，不是漏寫。**
如果不合併，使用者會看到兩支幾乎一樣的 skill——**那比少一支更糟。**

## DUP-2 · `DW_fmVmE9_i` — 與 `DYrcNJBAPWl` 幾乎逐字相同

| | |
|---|---|
| 分類器判定 | 兩支都 `WORTH_SKILL`（分類器仍無去重能力） |
| 人工判定 | **合併** —— 內容併入 `skills/style-extraction-invariants/`，不另立 skill |
| 重疊程度 | **比 DUP-1 高得多**：三個步驟的順序、用詞、舉例全部一致，連「你永遠只是在抄」「語意理合」這種特殊用語都一樣。**判定為同一支影片的二次上傳，不是同主題的兩支。** |
| 唯一實質差異 | 第三步的拆分板塊數：`DW_fmVmE9_i` 說「拆分成四個板塊」並列出四項；`DYrcNJBAPWl` 多列了一項「色板塊」共五項。已採五項版本並在 skill 中註明兩版不一致 |

**★ 第二次出現去重需求，而這次是逐字重複。**
DUP-1 是兩支同主題影片，DUP-2 是同一支影片。**兩者都只靠人讀抓到。**

**要不要實作去重？值得了，但不是用相似度門檻。**
逐字稿相似度可以抓 DUP-2（近乎相同），但抓不到 DUP-1（同主題不同用詞）；
而把門檻放寬到能抓 DUP-1，就會開始誤殺同系列的不同集數
（例如 `DY1v4xCju0t` 與 `DY3IkbwiDon` —— 作者自己說「第二個方法和上期一樣」，
但兩支處理的對象不同，**該保留兩支並互相交叉引用，不該合併**）。

**結論：先做「高相似度候選提示」不做「自動合併」**，把判定留給人。
n=2 仍然太少，記錄下來等第三個案例。
